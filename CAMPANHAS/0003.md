# Campanha 0003 — Fundação Executável do Projeto

- **Fase:** F1 — Fundação (0001–0006).
- **Baseline de entrada:** `IDB-FREEZE-AUTH-v5.5`, reconstrução normativa identificada e congelada antes do início desta campanha.
- **Estado:** PARTIAL.
- **Início:** após publicação e verificação da tag `IDB-FREEZE-AUTH-v5.5` em 2026-11-04 UTC.
- **Resultado anterior:** Campanhas 0001 e 0002 continuam PARTIAL/PARTIAL-BLOCKED; sem alteração retroativa.

## 1. Objetivo e entrada

Criar uma fundação npm workspaces executável com ESM, TypeScript strict, contratos Zod, Vitest, Fastify e shell web React/Vite mínimo. A entrada foi satisfeita pelo commit congelado `bdd1592990652bfdb79ed0e1809e76b042cdfd53`, tag anotada `IDB-FREEZE-AUTH-v5.5`, publicada e validada via GitHub. O checkpoint `CHECKPOINTS/v5.5.md` registra objeto e commit alvo da tag.

## 2. Escopo executado

- `package.json` privado com workspaces, engines, npm fixado em 11.21.1, ESM e scripts `build`, `typecheck`, `test`, `lint`, `verify`.
- Lockfile `package-lock.json`; contratos em `packages/contracts/{common,api,adapters,workers,persistence,schemas}`. Os contratos iniciais Zod cobrem intent de operação vinculado a fingerprint/hash/nonce/expiração, erro comum e health response.
- `apps/server`: shell Fastify/Pino, endpoint `/health`, bind padrão loopback, redaction básica de logger e shutdown graceful por SIGINT/SIGTERM.
- `apps/web`: React 19 + Vite, shell informativo mínimo e sem fluxos de administração.
- TypeScript strict, Vitest e ESLint configurados.
- Testes de contrato, HTTP smoke e processo filho Fastify iniciado em loopback e encerrado por SIGTERM.
- `.gitignore` atualizado para `coverage/` e `.vitest/`; README atualizado para a baseline reconstruída v5.5.

Commit local do código: `f44a21bb9ed6d4d8e947901d5b5b4ba671daad85`. Repositório de código `main`, worktree limpo. O remote de código continua sem refs e **não recebeu push**.

## 3. Fora do escopo e preservado para campanhas posteriores

Não foram criados adapters reais PostgreSQL/MySQL/MariaDB/SQLite, SQLite interno definitivo, migrations, WAL, vault, execução SQL, CRUD, workers duráveis, UI administrativa, Monaco, AG Grid, XYFlow, Zustand, TanStack Query, Tailwind, Playwright ou instaladores. Diretórios placeholder existentes (`.gitkeep`) foram preservados. Nenhum banco/serviço foi acessado; nenhuma operação SQL foi feita.

## 4. Instalação e validações

`npm install` inicial adicionou 191 packages, sem mudar ferramentas globais. `npm ci --fetch-retries=0 --fetch-timeout=120000` concluiu com sucesso em 43 s. Depois da instalação limpa, `npm run verify` terminou com código 0:

- build: contracts TypeScript, server TypeScript e Vite production build;
- typecheck: contracts, server e web;
- lint: ESLint nos fontes TS/TSX;
- teste: 3 arquivos, 5 testes, todos aprovados.

Build web Vite 8.3.5 transformou 16 módulos e gerou bundle em `apps/web/dist` (ignorado pelo Git). O smoke test fez request HTTP local, recebeu 200 e verificou shutdown. O teste de processo observou `server_started`, enviou SIGTERM e verificou exit 0.

## 5. Dependências e segurança

Versões diretas fixadas no lockfile: Node v26.4.0/npm 11.21.1; TypeScript 6.0.3; Vite 8.3.5; Vitest 5.1.0; React/ReactDOM 19.3.1; Fastify 5.12.8; Pino 10.4.0; Zod 4.6.7; ESLint 10.14.0; typescript-eslint 8.72.1.

Vite utilizou `rolldown@1.2.16` e o binding opcional `@rolldown/binding-android-arm64@1.2.16`; a instalação e o build passaram no Termux atual. Isso comprova somente este ambiente/execução, não suporte oficial a todos dispositivos Android.

`npm audit --omit=dev`: zero vulnerabilidades. Auditoria completa: 9 moderadas, zero altas/críticas, no conjunto dev ESLint/typescript-eslint/minimatch (finding informado como DoS por globparts amplification). Não foi executado `npm audit fix` nem alteração automática de versões; gate de segurança fica PARTIAL até triagem e correção compatível do toolchain.

Termux está em estado “toolchain disponível, build comprovado e testes executados”, mas não homologado para produção. Playwright E2E de interface completa é N/A, pois só existe shell estático mínimo.

Os estados de G1–G10 e EXIT-0003, com critérios/evidências, estão em `MATRIZES/GATES-0003.md` e `MATRIZES/EXIT-0003.md`.

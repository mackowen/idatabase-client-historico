# Matriz de compatibilidade e homologação

O estado observado é do ambiente/ferramentas, não de um produto que ainda não tem código. A matriz define o mínimo para uma futura declaração de suporte.

| Plataforma | Estado atual | Pré-requisitos / toolchain futura | Build e testes mínimos | Evidência e critério de suporte |
|---|---|---|---|---|
| Termux Android ARM64 | Ambiente observado (Android 13, `arm64-v8a`, Node 26.4.0); produto não testável. Clang Android API 24, Make/CMake, SQLite headers/lib disponíveis; node-gyp e NDK ausentes. | Node/npm fixados; headers e compilador Android; `node-gyp` compatível se houver addon; SQLite binding validado para Android/Bionic; armazenamento privado gravável. | Instalação limpa por lockfile, build de todos workspaces, testes unitários/contratos, integração SQLite, migrações/WAL/checkpoint/crash e processo filho. Registrar limitações de background Android. | Logs, versions, hashes do lockfile, ABI de addon e resultados de recuperação/concurrency. Suporte só após teste repetido em dispositivo Android ARM64 definido. |
| Linux ARM64 glibc | Não disponível; não testado. | Runner ARM64 real (Debian 12/13 ou Ubuntu 22.04/24.04/26.04), Node fixo, Python, make, C/C++ compiler, glibc, headers SQLite/libpq conforme dependências. | `npm ci`, build/lint/typecheck/unit/integration; compilar addons nativos no host; Playwright E2E em distro suportada. | CI log com uname/libc/Node/toolchain, artefatos e resultados. Não inferir compatibilidade a partir de Termux/aarch64. |
| Linux x64 | Não disponível; não testado. | Runner x86-64 Linux, versão de distro/libc fixada, Node, Python/make/compiler, headers nativos. | Fluxo completo de install/build/test; SQLite migrations/concurrency; E2E browser se UI existir. | CI reproduzível com lockfile, logs e artefatos; suporte somente após suíte obrigatória verde. |
| Windows x64 | Não disponível; não testado. | Windows 11+ ou Server 2019+ para Playwright; Node, Python e Visual Studio C++ Build Tools para addons, além das libs nativas selecionadas. | `npm ci`, scripts build/test, instalação dos addons em Windows, adaptadores SQLite/PostgreSQL e Playwright nos browsers acordados. | Runner Windows com versões, logs, artefatos e testes passantes. Não aceitar apenas TypeScript cross-platform como prova. |
| Docker | Docker CLI/daemon não disponíveis em Termux; sem Dockerfile no código; não testado. | Host Docker Engine habilitado; base image e arquitetura definidas; build context sem segredos; volumes/UID e storage documentados. | Build da imagem, startup, healthcheck, migrações em ambiente descartável, testes de integração e, se exigido, E2E com browsers. | Build/run logs por arquitetura; imagem identificada por digest. Docker só é requisito de suporte se o produto o declarar oficialmente. |

## Fatos oficiais considerados

- Playwright declara suporte a Chromium/WebKit/Firefox em Windows, Linux e macOS e lista atualmente Linux Debian 12/13 e Ubuntu 22.04/24.04/26.04 em x86-64/arm64, Windows 11+/Server 2019+ e macOS 14+. Android/Termux não aparece nessa lista; **a conclusão de que Termux não é alvo Playwright oficialmente enumerado é inferência da lista, não teste de incompatibilidade**. [Playwright installation/system requirements](https://playwright.dev/docs/intro#system-requirements).
- A documentação de Node-API descreve estabilidade ABI da API entre versões Node, mas isso não comprova compatibilidade de plataforma/arquitetura ou de bibliotecas externas. [Node.js ABI stability](https://nodejs.org/learn/modules/abi-stability).
- Para native addons, `node-gyp` documenta Python, make e compilador em Unix; Python >=3.12 requer `node-gyp` >=10. [node-gyp](https://github.com/nodejs/node-gyp#installation).
- SQLite WAL depende de shared memory/mesmo host, tem um writer por arquivo e exige considerar checkpoints; a versão do sistema observada não demonstra a versão linkada por addon futuro. [SQLite WAL](https://www.sqlite.org/wal.html).
